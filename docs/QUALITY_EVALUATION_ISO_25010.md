# NalaApps Macro v1.1.0 품질 평가

## 1. 평가 목적과 기준

이 문서는 NalaApps Macro v1.1.0을 ISO/IEC 25010:2023의 제품 품질 특성에 맞추어 프로젝트 수준에서 평가한다. 평가는 제품 요구사항, 소스 구조, 자동 테스트, CI 품질 게이트와 알려진 제약을 근거로 한다.

본 평가는 자체 품질 검토이며 제3자 공식 인증이나 표준 적합성 인증을 의미하지 않는다.

평가 등급:

- **충족**: 현재 범위에서 요구사항과 검증 근거가 충분함
- **부분 충족**: 핵심 통제는 있으나 실제 환경·추가 측정이 필요함
- **미평가**: 현재 범위에서 객관적인 근거가 부족함

## 3. 기능 적합성

### 구현 상태

- 키보드: A~Z, 0~9, F1~F24, 특수키, 조합키, 길게 누르기
- 마우스: 이동, 왼쪽·오른쪽·더블클릭, 휠, 고정·현재 위치
- 반복: 횟수 및 지정 시간 연속 클릭
- 문자: 한글·유니코드, 줄바꿈, 탭, 문자 간격
- 시간: 1~86,400초
- 편집: 추가, 상세 편집, 빠른 설정, 이동, 삭제
- 실행 제어: 반복, 무한 반복, 일시정지, 중지
- 파일: 저장·불러오기, 구형 스키마 호환

### 검증 근거

- 키 파싱 경계·오류 테스트
- 실행 명령 순서 테스트
- 마우스 반복·연속 실행 테스트
- 문자·Enter·Tab 테스트
- UI 이벤트 연결 정적 계약 테스트

## 4. 성능 효율성

### 긍정 요소

- 모든 기능은 로컬에서 동작하며 원격 API 대기가 없다.
- 반복 간격과 연속 실행 시간을 제한하여 무제한 자원 소비 위험을 줄였다.
- 문자 입력 간격을 조절할 수 있어 대상 프로그램의 처리속도에 맞출 수 있다.
- self-contained 단일 실행파일로 별도 런타임 설치 부담을 줄였다.

### 미측정 요소

- 24시간 무인 실행의 CPU·메모리 추이
- 10ms 간격 클릭의 실제 처리율과 손실률
- 다중 모니터·고DPI 환경의 좌표 지연

따라서 성능 효율성은 부분 충족으로 평가한다.

## 5. 호환성

- 지원 기준: Windows 10/11 x64
- 입력 방식: Windows user32 API
- 좌표: 다중 모니터의 음수·양수 좌표 허용
- 배포: .NET 8 self-contained win-x64
- 데이터: 스키마 v1 불러오기와 v2 저장

관리자 권한이 다른 프로그램, Windows 보안 데스크톱, 게임 안티치트, 브라우저 보안 영역 등은 운영체제·대상 프로그램 정책의 영향을 받는다.

## 6. 상호작용 능력

- 주요 기능은 모두 독립 버튼으로 제공된다.
- 문자 입력은 별도 다중행 편집창에서 직접 키보드로 작성한다.
- 동작 메뉴는 버튼 클릭 시 명시적으로 열리며 연속 클릭 등 세부 항목을 표시한다.
- 마우스·키·문자·시간 설정을 각각 목적에 맞는 대화상자로 분리한다.
- 실행 순서, 현재 상태, 반복 진행률을 표시한다.
- 파란색·빨간색 버튼은 흰색 글자로 고정한다.

남은 개선은 Tab 순서, 접근성 이름, 고대비 모드, 스크린리더 검증이다.

## 7. 신뢰성

- 실행 전 각 단계의 유효성을 전체 검사한다.
- Windows 입력 전송 실패를 예외로 보고한다.
- 키 누르기 동작은 취소·오류에도 역순으로 해제한다.
- 중지·종료 시 공통 보조키와 마우스 버튼을 해제한다.
- 잘못된 저장 파일을 실행 목록에 반영하기 전에 차단한다.
- 자동 테스트가 통과하지 않으면 배포 ZIP을 만들지 않는다.

## 8. 보안성

- 서버 통신·로그인·원격 제어 기능이 없다.
- 매크로 데이터는 사용자가 선택한 로컬 JSON 파일로만 저장된다.
- Windows 보안 조합인 Ctrl+Alt+Delete는 입력 단계에서 차단한다.
- 입력 문자열과 반복값은 허용 범위 검증 후 실행한다.

다만 사용자가 내려받은 매크로 파일의 출처 신뢰성, 파일 암호화, 디지털 서명은 현재 제공하지 않는다.

## 9. 유지보수성

### 구조 개선

- `KeyExpressionParser`: 키 표현식 해석
- `MacroStepValidator`: 입력 규칙과 경계값
- `IMacroInputDriver`: 운영체제 입력 추상화
- `WindowsMacroInputDriver`: 실제 Windows 입력
- `MacroExecutor`: 동작 실행 순서
- Dialog 클래스: 사용자 입력 수집
- MainWindow: 목록·실행 흐름 조정

이 분리로 실제 키보드나 마우스를 건드리지 않고 가짜 드라이버로 실행 엔진을 테스트할 수 있다.

### 품질 통제

- 경고를 오류로 처리
- 자동 회귀 테스트
- 단일 CI 워크플로로 중복 제거
- 테스트 계획·품질 평가·결과 보고서 유지

## 10. 유연성

- 현재 위치와 고정 위치를 선택할 수 있다.
- 한 번, 횟수 반복, 시간 연속 실행을 선택할 수 있다.
- 빠른 프리셋과 직접 숫자 입력을 함께 제공한다.
- 기존 단계를 상세 대화상자로 다시 편집할 수 있다.
- JSON 스키마가 신규 실행 옵션을 저장하면서 v1을 호환한다.

## 11. 안전성

- 긴급 중지: `Ctrl+Alt+F12`
- 최대 연속 실행: 86,400초
- 최대 반복 횟수: 100,000회
- 최소 클릭 간격: 10ms
- 무한 반복 시작 전 확인
- 실행 종료 시 입력 상태 정리
- Ctrl+Alt+Delete 차단
- 좌표와 저장 데이터 검증

## 12. 종합 판정

### 자동 배포 품질 게이트

다음 조건을 모두 충족할 때만 v1.1.0 배포 후보로 인정한다.

1. 자동 테스트 실패 0건
2. 애플리케이션·테스트 Release 빌드 경고 0건
3. self-contained 단일 EXE 생성
4. ZIP·SHA-256 생성
5. P0 알려진 결함 0건

### 최종 품질 판정

자동 품질 게이트를 통과한 빌드는 **기능·상호작용·신뢰성·유지보수성·유연성·안전성 측면에서 파일럿 정식 배포 후보**로 판정한다. 성능 효율성과 다양한 Windows 실행환경 호환성, 전문 접근성은 실제 사용자 환경의 추가 인수 테스트가 필요하다.
