# NalaApps Macro v1.1.0 테스트 계획

## 1. 문서 목적

이 문서는 NalaApps Macro v1.1.0의 테스트 범위, 위험, 접근 방법, 종료 기준과 산출물을 정의한다. 테스트 프로세스는 ISO/IEC/IEEE 29119 계열에서 제시하는 일반적인 테스트 계획·설계·구현·실행·완료 활동을 프로젝트 규모에 맞게 조정하여 적용한다.

이 문서는 제3자 인증서나 국제표준 적합성 인증을 의미하지 않는다.

## 2. 테스트 대상

- 제품: NalaApps Macro
- 버전: 1.1.0
- 플랫폼: Windows 10/11 x64
- 런타임: .NET 8 self-contained
- 주요 구성요소:
  - WPF 사용자 인터페이스
  - 키 표현식 파서
  - 동작 검증기
  - 키보드·마우스 실행 엔진
  - Windows 입력 드라이버
  - JSON 저장·불러오기
  - 전역 단축키와 취소·정리 처리

## 3. 테스트 목표

1. 모든 화면 버튼과 메뉴가 사용자에게 보이는 기능과 연결되어 있는지 확인한다.
2. 키보드, 마우스, 문자, 대기 동작이 설정값에 맞는 순서로 실행되는지 확인한다.
3. 반복·연속 실행·경계값·잘못된 입력을 검증한다.
4. 중지·취소·오류 발생 시 눌린 키와 마우스 버튼이 안전하게 해제되는지 확인한다.
5. 기존 저장 파일과 신규 저장 형식의 호환성을 확인한다.
6. 경고 없는 Release 빌드와 self-contained 단일 EXE 생성을 확인한다.

## 4. 테스트 범위

### 4.1 포함 범위

- A~Z, 0~9, F1~F24, 주요 특수키
- Ctrl·Alt·Shift·Win 조합키
- 키 한 번 누르기 및 지정 시간 누르고 있기
- 현재 위치 및 고정 좌표 마우스 이동·클릭
- 왼쪽·오른쪽·더블클릭
- 반복 횟수 및 지정 시간 연속 클릭
- 휠 위·아래 반복
- 한글·영문·숫자·유니코드 문자 입력
- Enter·Tab 처리와 글자 입력 간격
- 1~86,400초 대기
- 단계 편집·순서 변경·삭제
- 매크로 전체 반복·무한 반복·일시정지·중지
- JSON 스키마 v1 불러오기 및 v2 저장 왕복
- UI 버튼 이벤트 연결과 색상 버튼 글자 대비
- 빌드·테스트·배포 패키지 생성

### 4.2 제외 범위

- macOS·Linux
- Windows ARM64·32비트
- 보안 데스크톱에서 실행되는 Ctrl+Alt+Delete
- 관리자 권한이 다른 프로세스에 대한 입력 보장
- 온라인 게임 안티치트·보안 프로그램·원격 데스크톱의 제품별 호환성 보장
- 장시간 실사용 내구성에 대한 공식 성능 인증
- 접근성 전문기관 인증

## 5. 테스트 항목과 위험 기반 우선순위

| 위험 | 영향 | 가능성 | 우선순위 | 주요 통제 |
|---|---:|---:|---:|---|
| 마우스 클릭이 실행되지 않음 | 높음 | 높음 | P0 | 입력 드라이버 분리, 클릭 순서 자동 테스트 |
| 메뉴·버튼 클릭 무반응 | 높음 | 높음 | P0 | 모든 주요 Click 핸들러 정적 계약 테스트 |
| 키가 눌린 채 남음 | 높음 | 중간 | P0 | try/finally 역순 해제, 취소 테스트, 안전 해제 |
| 연속 클릭이 중지되지 않음 | 높음 | 중간 | P0 | 취소 토큰, 최대 시간, 긴급 중지 |
| 잘못된 반복값으로 과도한 실행 | 높음 | 중간 | P0 | 반복·간격·시간 상한 검증 |
| 문자 입력창 부재·입력 손실 | 중간 | 높음 | P1 | 별도 입력창, Unicode·Enter·Tab 테스트 |
| 저장 파일 손상·호환성 문제 | 중간 | 중간 | P1 | 스키마 검증, v1 호환, v2 왕복 테스트 |
| 색상 버튼 글자 식별 불가 | 중간 | 높음 | P1 | 흰색 글자 템플릿 계약 테스트 |
| 전역 단축키 충돌 | 중간 | 중간 | P2 | 등록 실패 사용자 경고 |
| 해상도 변경 후 좌표 불일치 | 중간 | 중간 | P2 | 위치 테스트와 사용자 안내 |

## 6. 테스트 접근 방법

### 6.1 정적 검증

- 경고를 오류로 처리하여 Release 빌드
- UI XAML에서 주요 버튼 이벤트 연결 확인
- 색상 버튼 템플릿의 흰색 글자 설정 확인
- 버전과 배포 파일명 일치 확인

### 6.2 단위·컴포넌트 테스트

- 키 표현식 파서
- 동작 입력값 검증
- 실행 엔진의 명령 순서
- 취소 시 키 해제
- 문자 특수문자 처리
- 직렬화 호환성

실제 운영체제 입력 대신 가짜 입력 드라이버와 가짜 지연기를 사용하여 결정적으로 검증한다.

### 6.3 통합·빌드 테스트

- WPF 프로젝트와 테스트 프로젝트 복원
- 두 프로젝트를 Release·warnings-as-errors로 빌드
- 자동 회귀 테스트 실행
- win-x64 self-contained single-file publish
- EXE 존재 확인
- ZIP과 SHA-256 생성

### 6.4 수동 인수 테스트

실제 Windows 데스크톱에서 다음 대표 시나리오를 확인한다.

1. 메모장에 `안녕하세요` 입력
2. Enter와 Tab이 포함된 여러 줄 문자 입력
3. Ctrl+A, Ctrl+C, Ctrl+V
4. Space 10초 누르기 후 정상 해제
5. 현재 위치 왼쪽·오른쪽·더블클릭
6. 고정 좌표 클릭
7. 10회 반복 클릭
8. 10초 연속 클릭 후 자동 종료
9. 연속 클릭 중 Ctrl+Alt+F12 중지
10. 50초 대기 설정 표시와 저장·불러오기
11. 각 버튼과 `동작` 메뉴 반응
12. 파란색·빨간색 버튼 글자 표시

## 7. 테스트 데이터

- 정상 키: A, Z, 0, 9, F1, F24, ENTER, SPACE
- 조합키: CTRL+C, CTRL+SHIFT+S, ALT+TAB, WIN+D
- 잘못된 키: UNKNOWN_KEY, 중복 CTRL+CTRL+C
- 차단 키: CTRL+ALT+DELETE
- 시간: 0.999초, 1초, 10초, 50초, 86,400초, 초과값
- 반복: 1, 2, 3, 100,000, 초과값
- 간격: 1ms, 10ms, 50ms, 100ms, 60,000ms, 초과값
- 문자: 한글, 영문, 숫자, 줄바꿈, 탭, 유니코드
- 좌표: 현재 위치, 양수 좌표, 다중 모니터 음수 좌표

## 8. 진입 기준

- 소스가 작업 브랜치에 반영되어 있다.
- .NET 8 SDK가 준비되어 있다.
- 테스트 하니스가 앱 프로젝트를 참조할 수 있다.
- 핵심 동작 계약이 코드로 정의되어 있다.

## 9. 종료 기준

- 자동 테스트 실패 0건
- Release 빌드 오류·경고 0건
- self-contained 단일 EXE 생성 성공
- ZIP·SHA-256 생성 성공
- P0 알려진 결함 0건
- P1 결함은 문서화되고 사용자 인수 여부가 결정됨
- 테스트 보고서에 범위·결과·잔여 위험 기록

## 10. 중단·재개 기준

다음 상황에서는 배포를 중단한다.

- 클릭·키·문자 중 핵심 동작 하나라도 자동 테스트 실패
- 취소 후 키 또는 마우스 버튼 해제 실패
- UI 버튼 이벤트 누락
- 저장 형식 회귀
- 빌드 경고 또는 publish 실패

원인 수정 후 전체 회귀 테스트를 처음부터 다시 실행한다.
